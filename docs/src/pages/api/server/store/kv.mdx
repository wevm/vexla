# Store.kv [Returns a store on a Cloudflare KV namespace]

The store keeps values and definitions in one KV namespace. [Cloudflare Workers](/guides/cloudflare-workers) shows the full setup.

```ts [src/index.ts]
import { Vexla, Store } from 'vexla/server'
import { definitions } from '../vexla.gen.js'

export default {
  async fetch(request: Request, env: { FLAGS: KVNamespace }) {
    // The binding exists only inside fetch.
    const vexla = Vexla.create({
      definitions,
      secret: process.env.VEXLA_SECRET,
      store: Store.kv(env.FLAGS),
    })
    return vexla.fetch(request)
  },
}
```

## Signature

```ts
// A store on a KV namespace
Store.kv(namespace: Store.KvNamespace): Store
```

`Store.KvNamespace` is the part of a KV binding that the store uses: `delete`, `get` with `'json'`, `list`, and `put`.

## Key Layout

| KV key             | Content                       |
| ------------------ | ----------------------------- |
| `value:<key>`      | the JSON value of a flag      |
| `definition:<key>` | the JSON definition of a flag |

- **Consistency:** KV is eventually consistent, so a write can take up to a minute to reach every location.
- **Definitions:** `definitions.delete` also deletes the value of the flag.
