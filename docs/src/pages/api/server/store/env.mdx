# Store.env [Returns a read-only store over environment variables]

The store reads each value from the variable of the same name as its key. It holds no definitions and has no `keys` operation. A write throws `Store.ReadOnlyError`, so the value routes of the admin API fail.

```ts [flags.ts]
import { Vexla, Store } from 'vexla/server'
import { definitions } from './vexla.gen.js'

export const vexla = Vexla.create({
  definitions,
  secret: process.env.VEXLA_SECRET,
  // Store values from process.env: NEW_CHECKOUT=true sets NEW_CHECKOUT.
  store: Store.env(process.env),
})
```

## Signature

```ts
// A store that reads variables
Store.env(variables: Record<string, string | undefined>): Store
```

## Behavior

- **Variable names:** the key of the flag, such as `NEW_CHECKOUT`.
- **Text:** each value is text. The instance decodes it for the type of the flag.
- **Order:** a store value precedes `decide`, so a variable of this store precedes `decide`. A variable that the instance reads through `env` follows `decide`.

## Errors

| Error                 | Thrown when                 |
| --------------------- | --------------------------- |
| `Store.ReadOnlyError` | `set` or `delete` is called |
