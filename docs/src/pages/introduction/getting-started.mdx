# Getting Started [Declare a flag, read it at build time or on the server, and change it without a deploy]

## Overview

Flargs is a self-hosted feature flag library. A committed flags file, `.env.flags`, declares each flag with its type and its default. A build flag resolves when the bundle builds. A runtime flag resolves on the server of the application for each request.

The server is optional. A project with build flags only needs no server, and adds a Flargs instance for runtime flags later. Reads of `flags` stay the same at each step. [Concepts](/introduction/concepts) defines each term.

## Agent Prompt

Paste this prompt into a coding agent:

```txt
Read github.com/wevm/flargs, add Flargs to my project, and put my unfinished work behind flags so it merges to main.
```

## Install

Install the package with a package manager. The `flargs` and `flargs/server` entries have no dependencies.

:::note
No release of the `flargs` package is published yet. The commands below apply after the first release.
:::

:::code-group

```sh [pnpm]
# Adds flargs to the project
pnpm add flargs
```

```sh [npm]
# Adds flargs to the project
npm install flargs
```

```sh [bun]
# Adds flargs to the project
bun add flargs
```

:::

## Setup

A server is optional. A project with build flags only needs a bundler plugin and no server. A project with runtime flags adds a Flargs instance to its server.

<Tabs stateKey="setup">
<Tab title="Build Time">

:::steps

### Declare the Flags

`.env.flags` declares every flag. The `@build` tag makes a build flag, which resolves when the bundle builds.

```sh [.env.flags]
# Show the maintenance banner.
# @type {boolean} @build @public
MAINTENANCE_BANNER=false
```

### Add the Plugin

`flargs/vite` writes `flargs.gen.ts` and replaces each read of a build flag with a literal. A library uses [`flargs/zile`](/guides/libraries) instead.

```ts [vite.config.ts]
import flargs from 'flargs/vite'
import { defineConfig } from 'vite'

export default defineConfig({
  // Reads .env.flags, writes flargs.gen.ts, and replaces build flag reads with literals.
  plugins: [flargs()],
})
```

### Read a Flag

The read needs no server. The bundle holds the value as a literal, so a minifier drops the dead branch.

```ts [main.ts]
import { flags } from 'flargs'

// Becomes `if (false)` in the bundle.
if (flags.MAINTENANCE_BANNER) showBanner()
```

### Set the Value

The plugin reads the variable from the environment of the build, then the default in `.env.flags`.

```sh
# Builds with the banner on
MAINTENANCE_BANNER=true npx vite build
```

### Declare the Flags

`.env.flags` declares every flag. A flag without the `@build` tag is a runtime flag, which resolves on the server for each request.

```sh [.env.flags]
# Use the new checkout flow.
# @type {boolean} @public
NEW_CHECKOUT=false

# Pricing page variant.
# @type {'a' | 'b' | 'c'}
PRICING=a
```

### Generate the Types

`flargs generate` writes `flargs.gen.ts`. The module holds the definitions, and registers their types for `flags`, `flargs.get`, and `useFlag`. The [Vite plugin](/guides/vite) writes the same module at startup and on each change of `.env.flags`.

```sh
# Writes flargs.gen.ts from .env.flags
npx flargs generate
```

### Create the Instance

`Flargs.create` returns the Flargs instance. The store holds the values that the admin API writes. `flargs.fetch` is a fetch handler for the dev route and the admin API.

```ts [flags.ts]
import { Flargs, Store } from 'flargs/server'
import { definitions } from './flargs.gen.js'

export const flargs = Flargs.create({
  definitions,
  // Dev mode accepts unsigned overrides for every flag, and opens the dev route.
  dev: process.env.NODE_ENV === 'development',
  // Signs overrides and share links. Required outside dev mode.
  secret: process.env.FLARGS_SECRET,
  // Holds store values in memory. A database or KV store keeps them across restarts.
  store: Store.memory(),
})
```

### Add the Middleware

The middleware serves the dev route at `/.flags`, and runs each other request in `Values.run`. [Hono](/guides/hono), [Node](/guides/node), [Next.js](/guides/nextjs), and [Cloudflare Workers](/guides/cloudflare-workers) each have a guide.

```ts [app.ts]
import { middleware } from 'flargs/hono'
import { Hono } from 'hono'
import { flargs } from './flags.js'

const app = new Hono()

// Serves /.flags, and scopes flags to each other request.
app.use(middleware(flargs))
```

### Read a Flag

`flags` holds the values of the current request.

```ts [app.ts]
import { flags } from 'flargs'

// Reads the value of the current request: an override, the store value, decide, or the default.
export function checkout() {
  return flags.newCheckout ? renderNewCheckout() : renderCheckout()
}
```

## Environment Variables

A flag reads the environment variable of the same name, so `NEW_CHECKOUT` reads `NEW_CHECKOUT`. `.env`, `.env.local`, or the deploy environment set the values that differ from the defaults.

```sh [.env]
# Values for this environment only. The file is not committed.
NEW_CHECKOUT=true
PRICING=b
```

A `.gitignore` entry such as `.env*` also ignores `.env.flags`. Add `!.env.flags` after it, so Git tracks the flags file.

```txt [.gitignore]
# Ignores local values, but tracks the flags file.
.env*
!.env.flags
```
