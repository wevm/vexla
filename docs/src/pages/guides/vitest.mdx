# Vitest [Runs each test with runtime flag values that the test declares]

## Overview

In a Vitest run, the [Vite plugin](/guides/vite) adds a setup file. Each test then runs in `Values.run`, so `flags` holds the default of each flag, or the value of its variable. `withFlags` of `vexla/vitest` returns test options that set runtime flag values for one test or one block.

| Options                           | Scope                  | Precedence                          |
| --------------------------------- | ---------------------- | ----------------------------------- |
| none                              | one test               | the defaults and the variables      |
| `withFlags(values)` on `describe` | each test in the block | over the values of the outer blocks |
| `withFlags(values)` on `test`     | one test               | over the values of each block       |

A build flag compiles to a literal, so a test cannot set it. Set the variable of a build flag in the environment of the test run instead.

## Walkthrough

### Add the Plugin

Vitest reads the Vite config, so the plugin of a Vite project also applies to its tests. A project without Vite adds the plugin to `vitest.config.ts`.

```ts [vitest.config.ts]
import vexla from 'vexla/vite'
import { defineConfig } from 'vitest/config'

// Adds the setup file in a Vitest run, and replaces each read of a build flag with a literal.
export default defineConfig({ plugins: [vexla()] })
```

### Set Values

`withFlags` receives the values, then the other options of the test or the block. A test file imports `test` and `describe` from Vitest.

```ts [pricing.test.ts]
import { describe, expect, test } from 'vitest'
import { withFlags } from 'vexla/vitest'
import { renderPricing } from './pricing.js'

// Runs with the default value of PRICING.
test('shows the monthly price', async () => {
  expect(await renderPricing()).toContain('per month')
})

// Runs with PRICING set to 'b', and a timeout of 10 seconds.
test('shows the annual price', withFlags({ PRICING: 'b' }, { timeout: 10_000 }), async () => {
  expect(await renderPricing()).toContain('per year')
})

// Each test in the block runs with PRICING set to 'c'.
describe('variant c', withFlags({ PRICING: 'c' }), () => {
  test('hides the trial', async () => {
    expect(await renderPricing()).not.toContain('trial')
  })
})
```

### Validate Values

The registered definitions type the values, so an unknown key, a value outside `options`, or a build flag is a type error. At runtime, the same values fail the test before it runs.

```ts [pricing.test.ts]
// Fails: No flag declares the key PRICNG.
test('typo', withFlags({ PRICNG: 'b' }), () => {})
```

## Recipes

### Every Option

A loop declares one test for each option of a select flag.

```ts [pricing.test.ts]
// One test for each variant.
for (const variant of ['a', 'b', 'c'] as const)
  test(`renders variant ${variant}`, withFlags({ PRICING: variant }), async () => {
    expect(await renderPricing()).toBeTruthy()
  })
```

### Concurrent Tests

`Values.run` scopes the values with `AsyncLocalStorage`, so concurrent tests with different values do not share them.

```ts [pricing.test.ts]
// Both tests run at the same time, each with its own value.
test.concurrent('variant b', withFlags({ PRICING: 'b' }), async () => {})
test.concurrent('variant c', withFlags({ PRICING: 'c' }), async () => {})
```

### Without the Plugin

A project without the plugin calls `setup` in its own setup file. The instance can then use `decide` or a store.

```ts [test/setup.ts]
import { aroundEach } from 'vitest'
import { setup } from 'vexla/vitest'
import { vexla } from '../flags.js'

// Registers the hook that runs each test in Values.run.
setup({ aroundEach, vexla })
```
