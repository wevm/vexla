# Rust [Reads the flags file at compile time, and parses the same overrides and signatures]

## Overview

The `flargs` crate reads the same flags file, override format, and signatures as the TypeScript packages. `flargs::flags!` parses `.env.flags` at compile time and generates typed flags, so Rust needs no generated file. A bad declaration fails the build.

| Crate                | Contents                                                                           |
| -------------------- | ---------------------------------------------------------------------------------- |
| `flargs`             | `Key`, `flargs::definitions`, `flargs::overrides`, and `flargs::flags!`            |
| `flargs-definitions` | the flags file parser, shared by `flargs` (as `flargs::definitions`) and the macro |
| `flargs-macros`      | `flargs::flags!`, re-exported by the `macros` feature (on by default)              |

## Walkthrough

### Declare the Flags

The crate reads the same `.env.flags` as the TypeScript packages. Each variable name is the key of its flag, so `NEW_CHECKOUT` declares `Flags::NEW_CHECKOUT`.

```sh [.env.flags]
# Show the maintenance banner.
# @type {boolean} @build @public
MAINTENANCE_BANNER=false

# Use the new checkout flow.
# @type {boolean} @public
NEW_CHECKOUT=false

# Pricing page variant.
# @type {'a' | 'b' | 'c'}
PRICING=a
```

### Generate the Flags

The path is relative to `CARGO_MANIFEST_DIR`.

```rust [src/flags.rs]
// Generates Flags, one Key for each runtime flag, one const for each build flag, and Pricing.
flargs::flags!(".env.flags");
```

| Generated item                | Example                                                                              |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| `Flags`                       | a struct with one typed field for each runtime flag, and `Default` from the defaults |
| a `Key` for each runtime flag | `Flags::NEW_CHECKOUT`, with `key()`                                                  |
| a const for each build flag   | `Flags::MAINTENANCE_BANNER`, from its variable at compile time, then its default     |
| an enum for each select flag  | `Pricing::A`, with `as_str()`                                                        |

### Build Constants

A build flag is a constant. A change of its variable rebuilds the crate. A JSON build flag is a `&str` that holds the JSON text.

```rust [src/main.rs]
// The compiler drops the branch when the constant is false.
if Flags::MAINTENANCE_BANNER {
    show_banner();
}
```

### Serve the Flags

`Runtime` resolves runtime flags for each request, in the same order as `Flargs.create`: an override, the store value, `decide`, the environment, then the default. `runtime.layer()` serves the dev route and the admin API under `/.flags`, and scopes values to each request.

```rust [src/main.rs]
use axum::{Router, routing::get};
use flargs::{MemoryStore, Runtime};

// One runtime per process. `decide` receives what `identify` returns.
let runtime = Runtime::<Flags>::builder()
    .decide(Flags::PRICING, |plan: &String| (plan == "enterprise").then_some(Pricing::C))
    .identify(|parts| plan_of(parts))
    .secret(std::env::var("FLARGS_SECRET")?)
    .store(MemoryStore::new())
    .build()?;

let app = Router::new()
    .route("/checkout", get(checkout))
    .layer(runtime.layer());
```

### Read a Flag

The `flargs::axum::Flags` extractor reads the runtime from the layer. `get` returns the typed value of one flag, and `evaluate` returns every runtime value.

```rust [src/checkout.rs]
// The extractor evaluates the flag for this request only.
async fn checkout(flags: flargs::axum::Flags<Flags>) -> Result<String, flargs::Error> {
    Ok(if flags.get(Flags::NEW_CHECKOUT).await? { "new".into() } else { "old".into() })
}
```

## Recipes

### Parse Overrides

`flargs::overrides::parse` applies the same rules as `Override.parse` in TypeScript. It verifies the signature before it parses values.

```rust [src/overrides.rs]
use flargs::definitions;
use flargs::overrides::{self, ParseOptions};

// Parses the query string of a request against the flags file.
let definitions = definitions::parse_file(include_str!("../.env.flags"))?;
let overrides = overrides::parse(
    "flag.PRICING=c&flag.exp=1767225600&flag.sig=3q2-7w",
    &ParseOptions { definitions: &definitions, dev: false, now, secret: Some(&secret) },
)?;
```

### Remote Store

With the `client` feature, `HttpStore` reads and writes the admin API of another Flargs server, such as a TypeScript admin service. It caches the manifest for five seconds. `reqwest` has no TLS backend by default, so a service that calls an `https` URL enables one on its own `reqwest` dependency.

```rust [src/main.rs]
use flargs::client::HttpStore;

// The token is a bearer token that the remote `authorize` accepts.
let store = HttpStore::new("https://api.example.com/.flags").token(std::env::var("FLARGS_TOKEN")?);
let runtime = Runtime::<Flags>::builder().secret(secret).store(store).build()?;
```

### Build Values From the Admin API

With the `build` feature, `flargs::build::pull` in `build.rs` sets each build flag variable from the admin API. A build flag then takes the store value, then the local variable, then the default.

```rust [build.rs]
// Reads the manifest with FLARGS_TOKEN and prints `cargo:rustc-env` lines.
fn main() -> Result<(), flargs::client::Error> {
    flargs::build::pull("https://api.example.com/.flags")
}
```

### Retirement

After [`flargs retire`](/cli/retire) removes a declaration from `.env.flags`, `flargs::flags!` no longer generates its items. `flargs retire` rewrites TypeScript reads only. Each read of the removed key fails to compile, so the compiler lists the reads to replace.
