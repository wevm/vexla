# Libraries [Publishes from main with unfinished work off, and with no runtime dependency on Vexla]

## Overview

A library merges unfinished work to `main` behind a build flag, and publishes from `main` with the flag off. A library has no request, so it declares build flags only and needs no server.

Zile transpiles the library with `tsc`. Its `transform` option names a module that rewrites each emitted `.js` file. `vexla/zile` replaces each read of a build flag with a literal and removes the `vexla` import, so `vexla` stays a dev dependency.

## Walkthrough

### Declare the Flag

The `@build` tag makes a build flag.

```sh [.env.flags]
# Use the new encoder.
# @type {boolean} @build
NEW_ENCODER=false
```

### Read the Flag

```ts [src/encode.ts]
import { flags } from 'vexla'

export function encode(value: string) {
  // Becomes `if (false)` in the published files. The bundler of the consumer drops the branch.
  if (flags.NEW_ENCODER) return encodeV2(value)
  return encodeV1(value)
}
```

### Configure Zile

:::note
The `transform` option of zile is not released yet ([wevm/zile#52](https://github.com/wevm/zile/issues/52)). zile `0.0.30` ignores it. Until the release, a builder calls `vexla/zile` from its own transform hook, as in [Other Builders](#other-builders).
:::

```jsonc [package.json]
{
  // zile runs vexla/zile on each emitted file, after tsc.
  "zile": { "transform": "vexla/zile" },
}
```

The emitted file holds the literal and no import:

```js [dist/encode.js]
// The vexla import is removed, since no read remains.
export function encode(value) {
  if (false) return encodeV2(value)
  return encodeV1(value)
}
```

## Recipes

### Prereleases

Each value resolves from its variable in the environment of the build, then its default. A CI job publishes a prerelease with the flag on.

```sh
# Publishes a build with the new encoder on
NEW_ENCODER=true pnpm build
```

### Runtime Flags

A read of a runtime flag, or a read with a computed key, fails the build. The error names the file and the line.

```txt
dist/pricing.js:2 reads PRICING, which is not a build flag.

To resolve: Add `@build` to the flag in .env.flags, since a library resolves build flags only.
```

### Types

`tsc` still emits the types of an unfinished export. Mark the export `@internal`, or keep it in an entry that the package does not publish.

### Other Builders

The transform is a function `(code, file) => string`. tsup, tsdown, and Rollup call it from their own transform hook. It reads `.env.flags` from the working directory of the build.

```ts [rollup.config.ts]
import transform from 'vexla/zile'

export default {
  input: 'src/index.ts',
  output: { dir: 'dist' },
  // Rewrites each module after the TypeScript plugin emits JavaScript.
  plugins: [{ name: 'vexla', transform: (code: string, id: string) => transform(code, id) }],
}
```
