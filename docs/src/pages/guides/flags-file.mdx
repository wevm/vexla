# Flags File [Declares every flag in .env.flags with its type and its default]

## Overview

The flags file, `.env.flags`, is the committed list of every flag. It uses dotenv syntax. Each variable declares one flag. Its name is the key of the flag, and its value is the default. The comment lines directly above the variable hold the description and the tags.

TypeScript and Rust read the same file. `.env`, `.env.local`, or the deploy environment set the values that differ from the defaults. A project with no Vexla instance and no store uses environment variables only.

## Walkthrough

### Declare a Flag

A `@type` tag declares the type. Without it, the type is inferred from the default: `true` or `false` is a boolean, a decimal is a number, a JSON object or array is JSON, and other text is a string. The variable name is the key, so `NEW_CHECKOUT` declares the flag that `flags.NEW_CHECKOUT` reads.

```sh [.env.flags]
# Use the new checkout flow.
# @type {boolean}
# @public
# @expires 2027-01-31
NEW_CHECKOUT=false

# Pricing page variant.
# @type {'a' | 'b' | 'c'}
PRICING=a

# A JSON object, so the type is inferred as {json}.
LIMITS={"requests":100}

# Show the maintenance banner. Several tags may share one line.
# @type {boolean} @build @public
MAINTENANCE_BANNER=false
```

| Tag        | Meaning                                                                          | Default  |
| ---------- | -------------------------------------------------------------------------------- | -------- |
| `@type`    | `{boolean}`, `{number}`, `{string}`, `{json}`, or a union such as `{'a' \| 'b'}` | inferred |
| `@public`  | the value may reach the browser                                                  | private  |
| `@build`   | the flag is a build flag, which resolves when the bundle builds                  | runtime  |
| `@expires` | a date (`YYYY-MM-DD`) after which the flag is due for retirement                 | none     |

A comment line without a tag is part of the description. A blank line ends the comment block, so a comment above a blank line does not apply to the variable below it.

A missing `@type`, an unknown type or tag, a default that does not match its type, or a key declared twice throws `Definitions.InvalidDeclarationError`. The error names the key and the line.

### Commit the File

A `.gitignore` entry such as `.env*` also ignores `.env.flags`. Add an exception after it, so Git tracks the flags file.

```txt [.gitignore]
# Ignores local values, but tracks the flags file.
.env*
!.env.flags
```

### Generate the Types

`vexla generate` writes `vexla.gen.ts`, which exports `definitions` and registers their types. The [Vite plugin](/guides/vite) writes the same module at startup and on each change of `.env.flags`.

```sh
# Writes vexla.gen.ts next to .env.flags
npx vexla generate
```

| `@type`        | Value type                                                      |
| -------------- | --------------------------------------------------------------- |
| `{boolean}`    | `boolean`                                                       |
| `{json}`       | the widened type of the default, such as `{ requests: number }` |
| `{number}`     | `number`                                                        |
| `{'a' \| 'b'}` | the union of the options, such as `'a' \| 'b'`                  |
| `{string}`     | `string`                                                        |

### Set Variables

`.env.flags` holds the defaults. `.env`, `.env.local`, or the deploy environment set the values for one environment. A flag reads the variable of the same name.

```sh [.env]
# Values for this environment. The file is not committed.
LIMITS={"requests":5}
NEW_CHECKOUT=true
PRICING=b
```

| `@type`        | Variable text                         |
| -------------- | ------------------------------------- |
| `{boolean}`    | `true` or `false`                     |
| `{json}`       | JSON text                             |
| `{number}`     | a finite number, such as `3` or `2.5` |
| `{'a' \| 'b'}` | one of the options                    |
| `{string}`     | any text                              |

The instance reads the variable after the override, the store value, and `decide`. An invalid value never selects a value. The instance passes `Definitions.InvalidValueError` to `onError`, and the error names the key but never holds the value.

### Check the Environment

`vexla check` fails when a variable holds a value that is not a value of its flag. With `--prefix`, it also fails on an undeclared variable with that prefix, so a typo such as `FEATURE_NEW_CHEKOUT` fails CI.

```sh
# Checks the process environment and the .env file
npx vexla check --env-file .env

# Also fails on a FEATURE_ variable that no flag declares
npx vexla check --env-file .env --prefix FEATURE_
```

## Recipes

### Rust

`vexla::flags!` reads the same file at compile time. A project with a TypeScript app and a Rust service keeps one `.env.flags`.

```rust [src/flags.rs]
// Generates typed flags from the flags file at the root of the crate.
vexla::flags!(".env.flags");
```

### No Server

Outside `Values.run`, `flags` reads the process environment. `flags.BETA` reads the variable `BETA`, and its type comes from the text: `true` and `false` are a boolean, a number is a number, a JSON object or array is JSON, and other text is a string.

```ts [script.ts]
import { flags } from 'vexla'

// BETA=true node script.ts reads the boolean true. An unset variable reads as undefined.
if (flags.BETA) enableBeta()
```

Without `.env.flags` or store definitions, `Vexla.create` declares no flags. A flags file adds defaults, options, and public flags, with no change to reads of `flags`.
