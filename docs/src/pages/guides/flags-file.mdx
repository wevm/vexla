# Flags File [Declares every flag in .env.flags with its type and its default]

## Overview

The flags file, `.env.flags`, is the committed list of every flag. It uses dotenv syntax. Each `FEATURE_*` variable declares one flag, and its value is the default. The comment lines directly above the variable hold the description and the tags.

TypeScript and Rust read the same file. `.env`, `.env.local`, or the deploy environment set the values that differ from the defaults. A project with no Flargs instance and no store uses environment variables only.

## Walkthrough

### Declare a Flag

Every flag needs a `@type` tag. The key comes from the variable name, so `FEATURE_NEW_CHECKOUT` declares `newCheckout`.

```sh [.env.flags]
# Use the new checkout flow.
# @type {boolean}
# @public
# @expires 2027-01-31
FEATURE_NEW_CHECKOUT=false

# Pricing page variant.
# @type {'a' | 'b' | 'c'}
FEATURE_PRICING=a

# @type {json}
FEATURE_LIMITS={"requests":100}

# Show the maintenance banner. Several tags may share one line.
# @type {boolean} @build @public
FEATURE_MAINTENANCE_BANNER=false
```

| Tag        | Meaning                                                                          | Default  |
| ---------- | -------------------------------------------------------------------------------- | -------- |
| `@type`    | `{boolean}`, `{number}`, `{string}`, `{json}`, or a union such as `{'a' \| 'b'}` | required |
| `@public`  | the value may reach the browser                                                  | private  |
| `@build`   | the flag is a build flag, which resolves when the bundle builds                  | runtime  |
| `@expires` | a date (`YYYY-MM-DD`) after which the flag is due for retirement                 | none     |

A comment line without a tag is part of the description. A blank line ends the comment block, so a comment above a blank line does not apply to the variable below it.

A missing `@type`, an unknown type or tag, a default that does not match its type, or a key declared twice throws `Definitions.InvalidDeclarationError`. The error names the key and the line.

### Commit the File

A `.gitignore` entry such as `.env*` also ignores `.env.flags`. Add an exception after it, so Git tracks the flags file.

```txt [.gitignore]
# Ignores local values, but tracks the flags file.
.env*
!.env.flags
```

### Generate the Types

`flargs generate` writes `flargs.gen.ts`, which exports `definitions` and registers their types. The [Vite plugin](/guides/vite) writes the same module at startup and on each change of `.env.flags`.

```sh
# Writes flargs.gen.ts next to .env.flags
npx flargs generate
```

| `@type`        | Value type                                                      |
| -------------- | --------------------------------------------------------------- |
| `{boolean}`    | `boolean`                                                       |
| `{json}`       | the widened type of the default, such as `{ requests: number }` |
| `{number}`     | `number`                                                        |
| `{'a' \| 'b'}` | the union of the options, such as `'a' \| 'b'`                  |
| `{string}`     | `string`                                                        |

### Set Variables

`.env.flags` holds the defaults. `.env`, `.env.local`, or the deploy environment set the values for one environment. The `envPrefix` option replaces `FEATURE_`.

```sh [.env]
# Values for this environment. The file is not committed.
FEATURE_LIMITS={"requests":5}
FEATURE_NEW_CHECKOUT=true
FEATURE_PRICING=b
```

| `@type`        | Variable text                         |
| -------------- | ------------------------------------- |
| `{boolean}`    | `true` or `false`                     |
| `{json}`       | JSON text                             |
| `{number}`     | a finite number, such as `3` or `2.5` |
| `{'a' \| 'b'}` | one of the options                    |
| `{string}`     | any text                              |

The instance reads the variable after the override, the store value, and `decide`. An invalid value never selects a value. The instance passes `Definitions.InvalidValueError` to `onError`, and the error names the variable but never holds the value.

### Check the Environment

`flargs check` fails when the environment sets a `FEATURE_*` variable that no flag declares, or a value that is not a value of its flag. A typo such as `FEATURE_NEW_CHEKOUT` therefore fails CI.

```sh
# Checks the process environment and the .env file
npx flargs check --env-file .env
```

## Recipes

### Rust

`flargs::flags!` reads the same file at compile time. A project with a TypeScript app and a Rust service keeps one `.env.flags`.

```rust [src/flags.rs]
// Generates typed flags from the flags file at the root of the crate.
flargs::flags!(".env.flags");
```

### Zero Config

With no definitions, `Flargs.create` declares a private flag for each `FEATURE_*` variable. The type comes from the value: `true` and `false` make a boolean, a number makes a number, a JSON object or array makes a JSON flag, and other text makes a string. The value is also the default.

```ts [flags.ts]
import { Flargs } from 'flargs/server'

// No flags file: FEATURE_BETA=true declares the private boolean flag beta.
export const flargs = Flargs.create({ dev: true })
```

Zero config has no options, no public flags, and no typo check. A flags file adds them later, with no change to reads of `flags`.
